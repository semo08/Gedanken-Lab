# 설계: EXP #05 이미테이션 게임 (7단계)

- 날짜: 2026-11-10
- 분야: 컴퓨터 · 판정형
- 시각 기준: 기존 실험의 실험 노트 스타일(`css/base.css`). 대화는 채팅 말풍선. 상대 X = 주황 `--a`, 상대 Y = 파랑 `--b`(색은 위치 구분용이지 정답과 무관).
- 짝 실험: EXP #06 중국어 방. 튜링의 주장(#05) → 설의 반박(#06) 순서로 이어진다.

## 1. 흐름 (`experiments/imitation/index.html`, `<section data-step>` 5개)

1. **소개**
   - 1950년 앨런 튜링은 "기계는 생각할 수 있는가?"라는 질문을 "대화만으로 기계를 사람과 구별할 수 있는가?"로 바꾸자고 제안했다. 원래 게임은 심판이 글로만 대화해서 두 사람 중 누가 남자이고 누가 여자인지 맞히는 놀이였다. 튜링은 한 자리를 기계로 바꿨다.
   - 규칙: 심판인 당신 앞에 상대 X와 Y의 대화 기록이 있다. 둘 중 하나는 사람, 하나는 기계다. 3라운드.
2. **라운드 1~3** (같은 레이아웃, 라운드마다 `data-step="r1"`~`"r3"`)
   - 심판의 질문 3~4개와 X, Y의 답이 말풍선으로 한 줄씩 나타난다(약 0.6초 간격, `prefers-reduced-motion`이면 한 번에). `건너뛰고 전부 보기` 링크.
   - 선택 카드 2개: "X가 기계다" / "Y가 기계다".
   - 고르면 바로 공개: 정답 여부, 기계의 정체(아래 시대 표), 기계가 들킨(또는 속인) 포인트 한 줄, 이 라운드 다른 실험자 정답률 막대.
   - `다음 라운드 →`.
3. **튜링의 질문**
   - "기계가 사람인 척을 완벽히 해서 아무도 구별하지 못한다면, 그 기계는 생각한다고 봐도 될까?" A 그렇다 / B 아니다.
4. **결과**
   1. 내 점수: 3라운드 중 n개 정답. 라운드별 정답·오답 칸.
   2. 라운드별 정답률: 나 vs 다른 실험자들(라운드마다 한 줄 막대).
   3. 튜링 질문 비율(A/B 막대) + 나의 답.
   4. 튜링의 예측과 실제: 튜링은 50년쯤 뒤(2000년 무렵)면 보통 심판이 5분 대화 뒤 기계를 맞힐 확률이 70%를 넘지 못할 거라고 예측했다. 2025년 UC 샌디에이고 연구(3자 대화, 5분)에서 사람처럼 행동하라는 지시를 받은 GPT-4.5는 73%의 경우 사람으로 판정됐다. 실제 사람보다 더 자주였다. 같은 실험에서 ELIZA는 23%.
   5. 고찰: 튜링의 기준은 "속을 들여다보지 말고 행동만 보자"는 입장이다. 그런데 사람처럼 대답하는 것과 이해하는 것은 같을까? → "EXP #06 중국어 방에서 반대편 주장을 직접 겪어 보자" 링크 카드.
   6. 참고 문헌, `↺ 다시 실험하기`, "다른 실험 해보기".

## 2. 라운드 구성 (`experiments/imitation/rounds.js`, 데이터)

| 라운드 | 기계의 시대 | 기계의 말투 특징 | 정답 힌트(공개 문구) |
|---|---|---|---|
| 1 | 1966년 ELIZA (와이젠바움) | 질문을 되돌려 묻기, 키워드 반복 ("왜 ~라고 생각하나요?") | 대답 대신 질문을 되돌려 줬다 |
| 2 | 2000~2010년대 규칙 기반 챗봇 | 캐릭터 설정으로 얼버무리기, 화제 돌리기, 엉뚱한 농담 | 곤란한 질문마다 화제를 돌렸다 |
| 3 | 2020년대 대규모 언어 모델 | 자연스럽고 맥락을 기억함. 사람 쪽이 오히려 오타·짧은 답 | 거의 구별이 안 된다. 오히려 사람이 더 대충 답했다 |

- 대화 텍스트는 직접 쓴 각본이다. 실제 AI를 호출하지 않는다(정적 사이트, 공개 레포라 API 키를 둘 수 없음).
- 사람 쪽 답도 시대와 무관하게 평범한 한국어 채팅 말투로 쓴다. 3라운드가 진짜로 어렵도록 사람 쪽에 오타, 줄임말, 성의 없는 답을 섞는다.
- 기계가 X인지 Y인지는 라운드마다 무작위로 정한다(`Math.random() < 0.5`). 그래야 정답률이 의미 있다.
- 라운드 데이터 형태: `{ era, label, reveal, turns: [{ q, human, machine }] }`.

## 3. 로직 (`experiments/imitation/judge.js`, 순수)

- `seat(random)` → `'X' | 'Y'` (기계 자리)
- `isCorrect(machineSeat, pick)` → boolean
- `score(results)` → `{ correct, total }`
- `layout(round, machineSeat)` → X, Y 말풍선 순서대로 정렬된 대화 목록

## 4. 데이터

- `votes/imitation_1` ~ `imitation_3`: `A` = 맞힘, `B` = 틀림. 라운드 공개 시점에 투표하고 곧바로 비율을 불러온다.
- `votes/imitation_turing`: `A` 그렇다, `B` 아니다. 결과 화면 진입 시.
- `firestore.rules`: `doc in [...]`에 4개 추가(키는 기본 A/B).
- 라운드 공개 시점 투표라 Firebase가 실패해도 라운드 진행은 막지 않는다. 정답률 막대 자리만 "불러오지 못했어요".
